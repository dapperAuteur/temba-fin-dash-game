Blog Post #3: Building the GraphQL API (Mutations and Queries)

Title: Dgraph Deep Dive: Crafting a Powerful GraphQL API with Mutations and Queries

Introduction:

In the previous posts, we set up Dgraph and designed our schema. Now, the real fun begins! We'll explore how Dgraph automatically generates a fully functional GraphQL API from our schema, allowing us to interact with our data using mutations (to create, update, and delete data) and queries (to retrieve data). We will use our financial data model as a concrete example.

1. Automatic API Generation:

The beauty of Dgraph lies in its automatic API generation.  Once you've defined your schema using the GraphQL SDL, Dgraph does the heavy lifting.  It creates all the necessary GraphQL types, queries, and mutations based on your schema definition.  This means you don't have to write any resolvers or backend code to get a basic CRUD (Create, Read, Update, Delete) API up and running.

2. Mutations: Modifying Your Data

Mutations are the GraphQL operations that allow you to change your data. Dgraph generates several mutations for each type in your schema:

add<Type>: Adds one or more new instances of a type.
update<Type>: Modifies existing instances of a type.
delete<Type>: Removes instances of a type.
Let's look at some examples using our financial data model.

2.1. Adding Data (add<Type>)

To add a new user, we'd use the addUser mutation:

GraphQL

mutation {
  addUser(input: [{ email: "jane.doe@example.com" }]) {
    user {
      id
      email
    }
  }
}
This mutation:

Uses addUser(input: [...]): The input argument takes a list of objects, each representing a new user to be added. Even if you're adding only one user, it must be in a list.
Specifies the fields to be set: email: "jane.doe@example.com".
Includes a selection set ({ user { id email } }): This determines which fields are returned in the response after the user is created. This is crucial. Without it, you won't see the results. The id is automatically generated by Dgraph.
Let's add an account for this user:

GraphQL

mutation {
  addAccount(input: [{
    user: { email: "jane.doe@example.com" } # Connect to existing user
    name: "Checking Account"
    plaidAccountId: "plaid_account_id_123"
    type: "Checking"
  }]) {
    account {
      id
      name
      user {
        id
        email
      }
    }
  }
}
This demonstrates connecting related objects:

user: { email: "jane.doe@example.com" }: We're linking the new account to the existing user by their email (because we defined email as @id). We could also have used the user's id.
The rest of the fields are set as scalar values.
2.2. Updating Data (update<Type>)

To update an existing account, we use the updateAccount mutation. This requires a filter to identify the account(s) to update, and a set or remove block to specify the changes.

GraphQL

mutation {
  updateAccount(
    filter: { id: ["0x2711"] }  # Filter by the account's ID
    set: { name: "Primary Checking", type: "Checking" }  # Update the name
  ) {
    account {
      id
      name
      type
    }
  }
}
filter: { id: ["0x2711"] }: We identify the account to update using its Dgraph-generated ID. You can filter by any indexed field.
set: { name: "Primary Checking", type: "Checking" }: We set the name to a new value.
2.3. Deleting Data (delete<Type>)

To delete an account:

GraphQL

mutation {
  deleteAccount(filter: { name: { eq: "Primary Checking" } }) {
    msg
    numUids
  }
}
This uses the deleteAccount mutation and, like updateAccount, requires a filter. This example shows how to use a filter other than id: name: { eq: "Primary Checking"}.

3. Queries: Retrieving Your Data

Queries are used to fetch data from your Dgraph database. Dgraph generates get<Type> and query<Type> queries for each type.

get<Type>: Retrieves a single object by its ID.
query<Type>: Retrieves a list of objects, optionally with filtering, ordering, and pagination.
3.1. Getting a Single Object (get<Type>)

GraphQL

query {
  getUser(id: "0x2711") {
    id
    email
    accounts {
      id
      name
    }
  }
}
This retrieves a single user by their ID and includes their associated accounts.

3.2. Querying with Filters (query<Type>)

GraphQL

query {
  queryAccount(filter: { type: { eq: "Checking" } }) {
    id
    name
    type
    user {
      id
      email
    }
  }
}
This query retrieves all accounts of type "Checking", along with their associated user information.  You can use various filter operators like eq (equal), ne (not equal), gt (greater than), lt (less than), ge (greater than or equal), le (less than or equal), in, alloftext, allofterms, and more, depending on the field's type and indexing.

3.3 Ordering

GraphQL

query {
    queryUser(order: {asc: email}) {
        email
    }
}
3.4 Pagination

GraphQL

query {
    queryUser(first: 10, offset: 2) {
        email
    }
}
4. Relationships and Nested Queries

One of the most powerful features of GraphQL is the ability to query related data in a single request. We already saw this in the getUser example, where we retrieved the user's accounts. You can nest queries to traverse your graph and retrieve all the data you need.

GraphQL

query {
  queryUser(filter: { email: { eq: "jane.doe@example.com" } }) {
    id
    email
    accounts {
      id
      name
      transactions {
        id
        amount
        date
        description
      }
    }
  }
}
This query retrieves a user, their accounts, and all the transactions associated with those accounts, all in one go!  This avoids the "N+1 query problem" common in REST APIs.

5. Using Variables

To make your queries and mutations more reusable, you can use variables:

GraphQL

mutation AddUser($email: String!) {
  addUser(input: [{ email: $email }]) {
    user {
      id
      email
    }
  }
}
You would then send the $email variable along with your request.  In curl, this would look like:

Bash

curl -X POST localhost:8080/graphql -H 'Content-Type: application/json' -d '{
  "query": "mutation AddUser($email: String!) { addUser(input: [{ email: $email }]) { user { id email } } }",
  "variables": { "email": "newuser@example.com" }
}'
Conclusion:

Dgraph's automatically generated GraphQL API makes it incredibly easy to start interacting with your data.  Mutations provide a simple way to add, update, and delete data, while queries, with their filtering and nesting capabilities, allow you to retrieve exactly the data you need, efficiently and effectively. This powerful combination forms the foundation of building sophisticated applications on top of Dgraph. In the next post, we'll delve into more advanced topics, such as custom logic and authorization.
